# Macy's Simulated Marketing Database

This folder holds the synthetic Macy's marketing dataset used by the Milestone 2 skills. The data is generated by Python scripts in `generators/` and written to `macys.db` (SQLite). Everything is reproducible from random seed 42.

## How To Build

From the `milestone02/` folder:

```
python data/generators/build_database.py
```

That script orchestrates all four generators in order, applies the schema in `schemas/schema.sql`, writes `data/macys.db`, and exports 100 row CSV samples to `data/samples/` for human inspection.

## Tables

### customers
50,000 rows. One row per Macy's customer.

| Field | Notes |
|-------|-------|
| customer_id | primary key |
| first_name, last_name, email | Faker generated. About 2 percent of email values are null to mimic incomplete CRM records. |
| age, gender | demographics |
| city, state, zip | US addresses |
| signup_date | up to 8 years before today |
| loyalty_tier | Bronze (60 percent), Silver (25 percent), Gold (12 percent), Platinum (3 percent) |
| star_rewards_points | scaled by tier |
| preferred_channel | email, app, or sms |
| opt_in_email, opt_in_sms | 0 or 1 flags |

Used by **audience-segment-builder**.

### transactions
About 500,000 rows. Purchase events.

| Field | Notes |
|-------|-------|
| transaction_id | primary key |
| customer_id | foreign key to customers |
| sku_id | foreign key to sku_catalog |
| transaction_date | within the last 24 months |
| unit_price | regional price at purchase time |
| quantity | small share of zeros to represent refunds |
| channel | online, instore, app |
| discount_pct | 0 to 0.5 |

Transaction frequency scales with loyalty tier (Platinum customers buy roughly 5x more often than Bronze).

Used by **audience-segment-builder** and **campaign-performance-analyzer**.

### sku_catalog
2,000 rows. Macy's product master.

Categories: Apparel, Beauty, Home, Accessories, Shoes (with realistic Macy's mix). Includes subcategory, brand, base_price, season, inventory_count, supplier.

Used by **dam-asset-finder** and **localization-generator**.

### regional_pricing
20,000 rows. 10 US regions x 2,000 SKUs.

Each row has the regional price (within plus or minus 10 percent of base_price) and an `in_stock_locally` flag.

Used by **localization-generator**.

### dam_assets
5,000 rows. Digital Asset Management records.

Asset types: hero, product, lifestyle, banner, social. Tags and associated_skus are stored as JSON lists. Includes filename, season, brand, created_date, last_used_date, file_size_mb, resolution, usage_rights (free, restricted, expired).

About 30 percent of assets carry a `degradation_flag` (mislabeled, duplicate, lowres, orphaned, expired). The rest are flagged `clean`. About 5 percent have empty tag lists. This mess is intentional, it tells the DAM degradation story from Milestone 1.

Used by **dam-asset-finder**.

### campaigns
12 rows. Marketing campaign briefs.

Realistic campaign names like "Spring Style Refresh 2026" and "Mother's Day Beauty Event 2026". Includes brief text, target_segment, dates, total_budget, and status (planned, live, completed).

Used by all four skills, especially **campaign-performance-analyzer**.

### campaign_performance
About 3,000 rows. Daily channel level metrics.

Channels: email, paid_social, display, search, instore. CTRs are realistic by channel (email about 3 percent, paid_social about 1 percent, display about 0.5 percent). Some campaigns have zero conversion days for realism.

Used by **campaign-performance-analyzer**.

## Reproducibility

Every generator pins `random.seed(42)`, `numpy.random.seed(42)`, and `Faker.seed(42)` so the data is identical across teammates. If you regenerate, the resulting `macys.db` will byte for byte match.

## Sampling

After build, `data/samples/` contains 100 row CSV slices of each table for quick eyeballing without opening SQLite.
